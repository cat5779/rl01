# S63 Cycle11 — reproducible proof certificates

## Mathematical claim and limits

The accompanying manuscript proves, by theory plus the finite certificates here,
`H_n''(a) <= -n/25 + 399` for the **actual** sine Toeplitz DPP with
`rho = 1/3`, `c = 19/20`, all `n >= 22`, and every
`a in [21/1000, 3/125]`. The corresponding entropy-rate chord modulus is `1/50`.
This is a proper-subinterval theorem; the whole `[.02,.03]` benchmark is **INCOMPLETE**.
It is a new submission, not an independently reviewed claim.

The executable certificates are NOT numerical sign scans. They verify:

1. A continuum bound for every conditional pair using a scalar analytical envelope.
2. All 256 guard words, on six continuous parameter cells, by outward interval subdivision of the full Loewner enclosure.
3. A complete 22-site actual-law finite expectation, using every one of the 4,194,304 configurations. Probability derivatives are retained by an exact nilpotent polynomial evolution.
4. The final interval sign by exact-rational Bernstein coefficients, including a proved polynomial-tail allowance.

## Build requirements

Use a Linux/x86-64 C++17 environment with GCC, OpenMP, and Boost headers.
The program checks that `long double` is radix 2 with 64 significand bits.
The verified run used GCC with `-O3 -frounding-math -ffp-contract=off`.
Do not enable fast-math, reassociation, or contraction.
The probability calculation uses Boost **checked** signed 256- and 512-bit integer types;
overflow throws instead of wrapping. It uses 192 fractional bits.
The largest executable uses roughly 0.7 GiB of memory plus runtime overhead.
The generated probability caches occupy about 160 MiB. They are intentionally not shipped.
Python 3's standard library is sufficient for the final exact rational test.

Run all commands from this extracted directory:

```sh
set -eu
CXX=${CXX:-g++}
FLAGS='-O3 -frounding-math -ffp-contract=off -std=c++17'
$CXX $FLAGS global_ratio_certificate.cpp -o global_ratio_certificate
$CXX $FLAGS -fopenmp guard_certificate.cpp -o guard_certificate
$CXX $FLAGS principal_probability_certificate.cpp -o principal_probability_certificate
$CXX $FLAGS payment_certificate.cpp -o payment_certificate
$CXX $FLAGS arithmetic_selftest.cpp -o arithmetic_selftest

./arithmetic_selftest
./global_ratio_certificate
./guard_certificate 6 -1 4 1000000
for prefix in 0 1 2 3; do
  ./principal_probability_certificate 22 2 "$prefix" "./prob22_${prefix}.bin"
done
./payment_certificate
python3 verify_rational_certificates.py
```

The four probability subtrees fix the first two bits to 00, 10, 01, and 11.
The payment verifier checks that every 22-bit word occurs exactly once and that
the mass interval contains one. It requires positive probability lower bounds,
valid PSD guard matrices, bounded test potentials, and successful parameter payment.
Missing or truncated probability data do not constitute a successful certificate.

The exact-rational Python test must be run after the payment program, because it
checks the newly generated coefficient intervals as well as the supplied guard data.
It proves every Bernstein coefficient is greater than `1/40000`; no floating
Bernstein evaluation is used. The finite subdivision checks use lower caps and
outward bounds and fail rather than accept a box that remains unresolved.

## Outward arithmetic

`cert_interval.hpp` uses an outward adjacent representable number after every
nonexact elementary operation, with a volatile result. Lower endpoints are the
negated corresponding upper operations. This strengthens the hardware rounding
setting; the proof does not rely merely on GCC's `-frounding-math` flag.
Zero/unit/cancellation shortcuts are exact. Logarithms use an elementary positive
atanh series and a geometric remainder after power-of-two range reduction.
Square roots are only candidate upper bounds until an outward square comparison
confirms them. Probability binary endpoints are compared to their exact integer
source before acceptance. Thus a library logarithm or unverified transcendental
value is not a proof input.

`arithmetic_selftest` additionally checks 138,828 inequalities against exact rational
arithmetic in all four rounding modes, including signed floor/ceiling division and
integer-to-binary endpoint conversion. It is an audit check, not a replacement for
the mathematical arithmetic enclosure argument.
