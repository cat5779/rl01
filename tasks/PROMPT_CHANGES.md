# 原提示为什么修改

这些是提示文本中可见的任务负担与逻辑问题；不能据此断言过去平台“思考失败”的内部原因。

| 原要求 | 新处理 | 原因 |
|---|---|---|
| 三轮必须串行，后轮消化前轮全部产物 | 五个对象固定、输入自含的独立研究题 | 不把一个大任务仅按时间切开 |
| 35/40/40 分钟 | 不指定内部思考时长，以可检查产物结束 | 经过时间不等于研究进展 |
| 至少八个工具，每个统一至少两条残差 | 一题一个命名瓶颈，最多选两个候选 | 不强迫未证的统一；允许真实结构深挖 |
| 必须三次候选失败与修复 | 有反例就记录；有证明就交付 | 不制造失败配额 |
| 每个候选覆盖所有类型 fixtures | 每题给适用域内的针对性反例入口 | rank-one、Toeplitz、循环投影不混同 |
| 一致尺度、固定宽区间先过 P5/P6 才晋级 | 当作更强升级结果 | 避免把未解主要定理设为起跑资格 |
| 只能留下一个解析缺口 | 按真实依赖列缺口及其相对强弱 | 防止把多个难题藏入“一个引理” |
| S13 的 moving-count 响应与真实律残差并列 | 单独增加真实律/修正律二阶桥接题 | 一模式匹配不等于全律二阶导数匹配 |
| checker、PR、ZIP 或完整性步骤失败就无法交付 | 完整正文可交付，工具状态单列 | 保留已完成数学成果 |
| 历史仓库清单检查 | 本次所有 Pro 任务不运行也不维护 | 用户明确要求取消哈希门 |

仍坚持：完整配置 Shannon 熵、真实后验、全部移动项与加速度、允许正负抵消、固定假设、合法反例、数值/有限证明/一般证明分开、不能把方法反例当目标反例。

最低可认可进展不含：复述本包恒等式、复述已知阈值、给一个新名字、无公式建议、把浮点拟合当定理、只说“需要证明一个引理”。INCOMPLETE 可以诚实交付；其新贡献只按实际已证子结果或排除的具体路线计算。
