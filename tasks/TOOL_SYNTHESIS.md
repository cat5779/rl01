# 跨领域数学工具合成：发现者与计算者分工

本版依据用户最新要求修订：五个独立任务都必须尝试创造可复用数学工具，优先探索 DPP 之外的可迁移机制；Pro 以理论推导为主，只做小算。

## 方法来源与改造

参考 [MathResearchPrompts 的完整模板](https://github.com/optsuite/MathResearchPrompts/blob/main/prompt_templates.md)：以第7项 Property-Constrained Object Synthesis 组织“背景固定、形式待造、性质待证”；第5/6项用于结构发现与跨场景迁移，第4项用于证明/反驳。第8项改为理论推导常数和尺度优先，仅用小例诊断；不照搬每候选必须运行代码的要求。第10项用于提示维护，不给每个发现者增加整套评测工作。

这是面向本项目的改造，不是安装外部 skill 或认证其效果。五题均内嵌完整职责与各自 P1–P3，单独复制即可启动，无须先读取本文件。

## 迁移要求

按障碍寻找域外结构，提交“源机制/定理条件 → 本题对象对应 → 条件缺口 → 新构造 → 可证性质”。领域名称本身不构成迁移；源定理需核对适用条件，无法核实的文献输入注明待核验。鼓励改造、组合已知机制，区分已有方法、迁移创新和未经查证的新颖性。

各题提供不同的域外种子供选择，并非已经适用的定理清单。无需覆盖所有领域；优先深化一个有具体公式的方向，失败时根据精确障碍改道。不能仅列想法或换名定义原未知量。

## 计算边界

Pro：构造对象、推导恒等式和界、用极限/端点分析常数尺度、证明局部引理、寻找符号反例；必要时做最小实例的短小检验。

后续计算者：大规模枚举、参数扫描、长优化、高精度认证、渐近拟合。发现者只需交待测公式、域、判别问题、误差标准与其对引理的影响，不写计算平台，不等待重算。

数学状态与工具状态分开。未认证数值只作线索；仍可交付候选、已证部分和缺口。没有强制时长、候选配额、失败轮数、哈希或打包验收。

## 有效交付

成功构造：明确对象、适用域、逐项性质证明及对瓶颈的作用。
构造未成：明确候选、已证子性质、反例/缺口及修正方向；不得把它标成已证明工具。
反驳某候选不等于反驳全局熵凹性；有限证据不自动推出成长尺度结论。
